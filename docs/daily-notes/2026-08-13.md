  - Daily note habit started, this file + `TEMPLATE.md`
    ([PR #6](https://github.com/nahunp/todo-app/pull/6), merged)
- **Validated `PROMOTE_TOKEN` end to end** instead of assuming it worked —
  found and fixed three real bugs that would otherwise have broken the
  nightly promotion silently:
  1. Secret didn't actually exist on the repo yet — the PAT existed in
     Diego's account but was never attached as a repo secret. User error,
     easy fix, but `gh secret list` / the Actions API was the only way to
     tell for sure (the PAT list page looks similar enough to cause
     confusion).
  2. `gh pr merge --auto` fails with *"Pull request is in clean status"* on
     essentially every real run — `backend-ci.yml`'s `push` trigger already
     puts a passing `build-and-test` check on the commit before the
     promotion PR is even opened, so auto-merge (meant for PRs still
     waiting on checks) refuses. Fixed with a fallback to a direct merge
     ([PR #9](https://github.com/nahunp/todo-app/pull/9)).
  3. `strict` status checks on `master`'s protection deadlock every
     promotion *after* the first — each promotion leaves the target branch
     one merge-commit ahead of the source, which `strict` reads as "source
     not up to date," permanently blocking. Fixed by turning `strict` off
     for promotion targets (doesn't make sense for a one-way pipeline
     anyway).
  - One-time manual bootstrap promotions required twice today (
    [PR #7](https://github.com/nahunp/todo-app/pull/7),
    [PR #8](https://github.com/nahunp/todo-app/pull/8)) — `schedule` and
    `workflow_dispatch` triggers only fire for workflow files that already
    exist on the **default branch**, so a brand-new promotion workflow
    can't run itself into existence; someone has to manually promote it
    through once.
- **Split the single-hop promotion into a proper staging pipeline**, closer
  to a real enterprise SDLC:
  ```
  development --(daily, 00:00 Mexico City)--> release --(every 2 days)--> master
  ```
  - New `release` branch, protected the same way as `master` — PR required,
    `build-and-test` required, `strict: false` applied from the start this
    time (no need to rediscover bug #3 above)
  - `promote-development-to-release.yml` (new, daily) and
    `promote-release-to-master.yml` (renamed from `promote-to-master.yml`,
    now every 2 days via `cron: 0 6 */2 * *`)
    ([PR #11](https://github.com/nahunp/todo-app/pull/11), merged)
  - Bootstrapped both new hops through to `master` manually so the pipeline
    is live immediately instead of waiting up to ~2 days
    ([PR #12](https://github.com/nahunp/todo-app/pull/12),
    [PR #13](https://github.com/nahunp/todo-app/pull/13))
  - Confirmed via manual `workflow_dispatch` on both stages: clean,
    unattended, no errors

**End of day state**: `development` → `release` → `master` is fully
automated end to end, no approval required at either promotion hop. Feature
work still flows through manual review into `development` as before —
that part was never meant to be automated.
