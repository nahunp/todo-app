- Designed and implemented `TodoList`, the aggregate root that owns
  `TodoItem`s — the Aggregate Root pattern in practice: a single point of
  mutation for rules that span multiple items, here "no duplicate titles
  within a list" (case-insensitive, trimmed). `TodoItem` itself is
  unchanged — still owns its own invariants. `RenameItem`/`RemoveItem`
  take the `TodoItem` reference rather than an `int` id, since `Id` is
  DB-assigned and stays `0` until `SaveChanges` runs, so an id-based
  lookup couldn't tell freshly-added siblings apart. Called out explicitly
  in code comments: `TodoItem.Rename` stays `public` (needed so
  `TodoItemTests` keeps testing it standalone), so the uniqueness check is
  a convention (`TodoList.RenameItem`, not `item.Rename` directly) rather
  than something the compiler enforces. 37 tests passing (16 existing +
  21 new) in Visual Studio's Test Explorer.
