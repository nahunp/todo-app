  `DbUpdateConcurrencyException` (500) instead of a sensible response.
  Now maps to 404 in `GlobalExceptionHandler`. Also added
  `EnableRetryOnFailure()` for Azure SQL's free-tier serverless
  cold-start (confirmed via the App Service log stream, not guessed —
  Error 40613 the first time, a straight command timeout the second).
- **[PR #52](https://github.com/nahunp/todo-app/pull/52)** — documented
  the deployment in README.md and CLAUDE.md.

  (Copilot's auth UI, issue #44) — see the frontend note for the two
  review rounds that preceded today's third and merge.
- Verified live end-to-end on the real deployed infra, not just unit
  tests: register → login → token auto-attaches → create/view/delete a
  list → logout clears everything → route guard blocks unauthenticated
  access → the concurrent-delete fix confirmed by deliberately
  reproducing the race against the real API.
- **[PR #54](https://github.com/nahunp/todo-app/pull/54)** — added the
  Cloud Dancer brand standards (`docs/design/brand-standards.pdf`) as a

  images (`poppler`) and read them visually, not extract text.
- **[PR #56](https://github.com/nahunp/todo-app/pull/56)** — added
  `Priority`, `DueDate`, and `Category` to `TodoItem`
  (Domain → Application → WebApi), driven by the brand standards'
  "todo-specific patterns" section: new `TodoItemCategory`/`DueDateState`
  enums, three new `Set*` commands, enums serialize as their string names
  (`JsonStringEnumConverter` + a custom `EnumSchemaFilter`, since
  Swashbuckle doesn't pick up the converter for the OpenAPI schema on its
  own — confirmed by actually diffing the regenerated spec, not assumed).
- **[PR #57](https://github.com/nahunp/todo-app/pull/57)** — found live
  while shipping the frontend branding work below (double-click testing
  the deployed app): a concurrent add/rename could create two items with
  the same title in the same list — the uniqueness check was in-memory
  only, no DB backing. Added a unique index and mapped the resulting
  `DbUpdateException` to 400. Verified with genuinely concurrent
  PowerShell background jobs, not sequential calls.
- **[PR #59](https://github.com/nahunp/todo-app/pull/59)** — Diego hit a
  registration 400 on the live site; turned out to be Identity correctly
  rejecting a weak password, not a bug — but exposed a real gap: the
  password policy was implicit and there was no way for a user to see
  requirements before submitting. Added `GET /api/v1/auth/password-policy`
  and, since Diego's about to share the live link publicly, Cloudflare
  Turnstile CAPTCHA on `/register` (verified server-side, before Identity
  is ever touched, so a bot doesn't cost a real `CreateUserAsync`/DB
  round-trip per attempt).
- Diego set up the real Turnstile site and the real secret key himself
  directly in Azure App Service settings — never shared in chat, per the
  standing secrets policy. Confirmed working in production by testing
  that a fake token is now rejected.
- Ran a full housekeeping pass on the Claude Code setup itself (unrelated
  to the app) — nothing unused to clean up; turned on auto permission
  mode.
- **Deployment automated** — `backend-deploy.yml` / `frontend-deploy.yml`
